# Career Positioning

Author: Özay Kocak

Kojak Street is intended as a portfolio project for roles at the intersection
of finance, software engineering and AI-assisted model development.

## Project Narrative

The project began from a long-standing personal interest in economics,
politics, history, financial markets, macroeconomics and monetary systems.

Özay Kocak trained as a banker and worked for several years in banking,
including customer service and advisory work across savings, building-society
products, securities, loans and private-client banking.

Kojak Street started as a small broker-terminal trading game with a simple
macro simulation. Through iterative development it became a broader financial
simulation system with supply chains, macro drivers, companies, bonds,
derivatives, portfolio risk, tests and a modern desktop UI.

The project was built autodidactically through learning by doing, feedback
from software-developer friends, extensive self-study and practical use of
LLMs as coding and architecture assistants.

## How LLMs Were Used

LLMs were used as development collaborators for:

- architecture planning
- feature decomposition
- code generation and refactoring
- debugging
- test design
- documentation
- reviewing model logic and edge cases

The financial ideas, product direction, feature priorities and final decisions
were driven by Özay Kocak. The project demonstrates the ability to combine
domain knowledge with AI-assisted software development.

## What The Project Taught Me

Through Kojak Street, I learned how to turn a broad financial idea into a
working software system. Starting without formal programming education, I built
practical skills in Python, object-oriented programming, Visual Studio Code,
project structure, testing, debugging and iterative optimization.

The project also taught me how to work effectively with LLMs: not as a
replacement for my own thinking, but as a planning, research, coding,
refactoring and UI-design partner. I learned to break large ideas into smaller
implementation steps, challenge model assumptions, review generated code,
debug errors, improve performance and keep the product direction under my own
control.

Most importantly, I learned that I can combine my banking background and
long-standing interest in financial markets with modern AI-assisted software
development to build systems that are both technically functional and
financially meaningful.

## Roles To Explore

Based on current job postings and the project profile, realistic target roles
include:

- AI Engineer in financial services
- Financial Modeling Engineer
- Risk Analytics / Risk Model Developer
- Quant Developer, especially junior or hybrid roles
- Portfolio Analytics Developer
- Trading Tools Developer
- FinTech Product Engineer
- Business Analyst / Product Owner with strong technical prototyping skills
- Model Risk / Analytics roles with a path toward model development

Some senior quant roles require advanced mathematics, C++, Java, regulatory
modeling or a quantitative degree. Those may be harder as first targets.
Hybrid finance-plus-AI roles, analytics engineering roles and financial
technology product roles are more realistic entry points.

## Realistic Chance Assessment

This project does not replace a computer-science or quantitative-finance
degree for highly specialized senior quant roles. It can, however, be a strong
differentiator for roles that value domain knowledge, curiosity, practical
prototyping and AI-enabled delivery.

The strongest path is to present the project as evidence of:

- financial intuition
- systems thinking
- software-learning ability
- persistence
- product ownership
- responsible use of AI tools

For applications, the project should be paired with a concise CV, a strong
GitHub repository, screenshots or a short demo video, and a short explanation
of model assumptions and limitations.
